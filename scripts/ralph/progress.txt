## Codebase Patterns

- Use `cn()` from `@/lib/utils` for className merging
- shadcn/ui components go in `components/ui/`
- Path alias `@/*` maps to project root
- Color palette: cream (#FAF7F2), coral (#E07A5F), deep brown (#3D2E2E)
- Status colors: Draft (#9CA3AF), In Review (#F59E0B), Approved (#10B981), Live (#E07A5F)
- Database: Drizzle ORM with Vercel Postgres, schema in `lib/db/schema.ts`
- Database connection: `db` export from `@/lib/db`
- Migrations: `bun run db:generate` to generate, `bun run db:push` to push to DB
- DB scripts use `dotenv-cli` to load `.env.local` automatically
- Need `POSTGRES_URL` alias in `.env.local` pointing to `menutrackerdb_POSTGRES_URL`
- API routes: Use `getCurrentUser()` from `@/lib/auth` to check auth
- Role checks: Compare `user.role` against allowed roles
- CSV export: Use `escapeCSV()` helper for proper quoting
- Tags: Junction table `menuTags` links menus to tags, batch fetch to avoid N+1
- Settings page: Admin-only, tabs for Users/Categories/Tags at `/settings`

## 2026-01-19 - Tags on Menus Feature

Added ability to assign tags to menus (not part of original PRD, added as enhancement).

**What was implemented:**
- GET /api/menus now returns tags for each menu (batch fetched)
- POST /api/menus accepts `tagIds` array to assign tags at creation
- New menu form shows tag selection with colored pill buttons
- Dashboard menu cards display tags with matching colors
- Dashboard page fetches and passes tags to cards

**Files modified:**
- `app/api/menus/route.ts` - Added menuTags/tags imports, batch fetch tags in GET, insert tags in POST
- `app/menus/new/page.tsx` - Added Tag interface, state, fetch, toggleTag function, tag buttons UI
- `app/page.tsx` - Added batch tag fetching, pass tags to DashboardFilters
- `components/dashboard-filters.tsx` - Added Tag interface to Menu type, pass tags to MenuCard
- `components/menu-card.tsx` - Added Tag interface, tags prop, tag badge rendering

**Learnings:**
- Use `inArray()` from drizzle-orm for batch queries
- Batch fetch related data after main query to avoid N+1
- Tag colors stored as hex, render with `backgroundColor: color + "20"` for transparent bg

Raffy needs visual markup on PDFs - checkmarks, strikethroughs, text notes, year/price changes.

**Reference:** User shared wine list PDF with manual markup showing:
- ✓ checkmarks for approved items
- Strikethrough old values + new values (2023 → 2024, £16 → £15)
- "to be removed" text annotations
- Highlight boxes around changes
- Bracket grouping for related items

**Implementation approach:**
1. Create `annotations` table in schema (versionId, pageNumber, type, data JSON, createdBy)
2. Canvas overlay component on PDF viewer
3. Drawing tools: pen, text, checkmark stamp, highlight
4. Store annotations as vector data (paths, positions, colors)
5. Render annotations on top of PDF
6. API: GET/POST /api/versions/[id]/annotations
